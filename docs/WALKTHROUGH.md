# Understanding Folio before an interview

Use this as a study guide. Read the actual files, run the app, and explain only what you understand. Do not claim unaided authorship or experience you do not have; describe tools and assistance honestly if asked.

## 1. What runs where?

Angular is TypeScript compiled to JavaScript that runs in the browser. C# runs in ASP.NET Core on the server. PostgreSQL runs remotely in Neon.

Angular cannot directly access the database password. It asks the API for data using HTTP. The API validates the request and uses Entity Framework Core to read or write PostgreSQL.

During local development there are two processes: Angular's development server and the .NET API. The Angular proxy sends /api requests to .NET. In production, .NET serves the already-built Angular files too, so everything has one HTTPS address.

## 2. What happens when I add a book?

1. The Add New Book link navigates to /books/new without a full page reload.
2. EditorPage builds a reactive form. Angular tracks field values, touched state and validation errors.
3. Submit trims strings, validates the form and disables repeated submission.
4. ApiService gets a CSRF token and sends POST /api/books with JSON.
5. Authentication checks the signed JWT cookie and its server-side session record.
6. Antiforgery validation checks that the write came with the correct token.
7. ASP.NET validates the request DTO. Client validation is helpful but the server still validates untrusted input.
8. BooksController creates a Book object and calls SaveChangesAsync.
9. EF Core translates the change into parameterized SQL. PostgreSQL assigns an ID and persists the row.
10. The API returns 201 Created. Angular navigates back to the library and reloads its books.
11. Refreshing still shows the book because it lives in PostgreSQL, not just a JavaScript array.

Read: client/src/app/editor.ts, core.ts; server/Controllers/BooksController.cs; Data/AppDbContext.cs.

## 3. C# concepts compared with C++

- A class defines a reference type. Objects are garbage-collected; you usually do not manually delete them.
- An interface defines a contract. Dependency injection supplies implementations such as a password hasher or database context.
- async/await allows the thread to do other work while an HTTP or database operation waits. It is not a command to create a new thread for every method.
- Task<T> represents an asynchronous result.
- LINQ Where, Select and OrderBy express filtering, projection and ordering. With EF queries, supported expressions become SQL.
- Nullable types express whether a value can be absent. DateOnly? can be missing, so the request validator requires it before use.
- Attributes such as [Authorize], [HttpPost] and [Required] attach behavior/metadata.
- using can import a namespace or manage disposal of a resource.
- A DTO (data transfer object) specifies accepted input independently from a stored database entity.

## 4. How authentication works

Registration stores a salted password hash generated by ASP.NET Core PasswordHasher. It never stores the original password.

Login verifies that hash, creates a one-hour session row, and signs a JWT containing a user ID, username and session ID. The JWT is encoded and signed, not encrypted. Do not put secrets in its claims.

The server sends it in an HttpOnly cookie. The browser sends that cookie on subsequent same-origin requests; JavaScript cannot read it. In production, Secure requires HTTPS and SameSite=Strict limits cross-site sending.

The API checks signature, issuer, audience and expiry, then checks that the session still exists. Logout deletes the session row, so even a copied JWT no longer works.

There is no refresh token. After one hour the user signs in again. This is a deliberate small-app tradeoff.

## 5. Why both JWT and CSRF protection?

Cookies are attached automatically by browsers. That convenience can let another site attempt requests using a victim's session. The antiforgery system provides a request token which Angular reads from XSRF-TOKEN and sends as X-XSRF-TOKEN. The server validates it against its protected antiforgery cookie and the current identity.

The authentication cookie is HttpOnly. The separate CSRF request token must be readable by Angular. They serve different purposes.

## 6. How quote privacy works

Each quote has UserId. The API obtains the current user ID from the validated JWT, never from a client-provided owner field.

Queries for list, read, update and delete constrain UserId. Asking for another user's quote ID returns 404. Hiding a button in Angular would not be sufficient; the API enforces ownership.

Books are intentionally shared between authenticated users.

## 7. Database and migrations

AppDbContext connects entities to tables. Npgsql is the PostgreSQL provider. The connection string identifies the host, database, role and password; TLS protects the database connection in transit.

A migration is a versioned description of schema changes. InitialCreate made Books. AddAccountsAndQuotes added Users, Quotes and Sessions, foreign keys and indexes. __EFMigrationsHistory records applied migrations.

SaveChangesAsync saves data; database update applies schema migrations. These are different operations.

A unique index on NormalizedUsername prevents duplicate usernames, including concurrent registrations. A foreign key keeps quotes and sessions tied to real users. Production uses PostgreSQL; automated tests use isolated SQLite databases, which is a testing limitation to acknowledge.

## 8. Angular concepts

- Component: a TypeScript class paired with an HTML template.
- signal: a reactive value; updating it refreshes the UI that reads it.
- computed: derives filtered or sorted collections from signals.
- Reactive form: explicit controls with validators and state.
- Router: switches views inside the single-page app.
- Guard: sends signed-out users to login for a smoother experience; API authorization remains the security boundary.
- HttpClient: issues JSON requests. firstValueFrom lets async methods await its observable.
- Interceptor: handles expired-session responses consistently.
- Service: shares logic/data across components rather than duplicating HTTP code.

## 9. Why dates need care

A publication date is a calendar date, not an instant. The backend uses DateOnly and JSON YYYY-MM-DD. For display, the template appends midnight UTC and formats in UTC so browser timezone conversion cannot move it to the previous day.

## 10. What makes the UI resilient?

Loading, empty and failure states explain what is happening. Failed saves leave the user's input in the form. Buttons disable while requests run. Delete asks for confirmation. Forms and buttons have labels, visible focus and mobile layouts. Theme preference is the only app setting stored in localStorage; the JWT is not.

## 11. What would you improve with more time?

- Upgrade the required framework versions to supported LTS versions for long-term use.
- Password recovery and email verification.
- Pagination for a large library.
- Optimistic concurrency to prevent one edit silently overwriting another.
- PostgreSQL integration tests in containers, in addition to SQLite tests.
- Trusted proxy and distributed rate-limit configuration.
- Operational monitoring and a dedicated migration release step.
- Broader real-device and browser coverage, including iOS Safari.

## A short demo to practise

Register → sign in → add a book → edit it → refresh → search → add/edit/delete a quote → switch theme → narrow the screen → sign out.

Then open BooksController and explain one method line by line. Repeat for EditorPage.save and AuthController.Login. If you cannot explain a line, investigate it before describing it as your own expertise.
